# ДЗ №1. ВышКат

Интерактивное консольное приложение на Python для учёта транспорта и вещей на
балансе кикшеринга.

## Запуск

Требуется Python 3.11 или новее. Дополнительные библиотеки не нужны.

```bash
cd task_1
python3 -m vyshkat.main
```

После запуска приложение ожидает команды пользователя. Все данные транспорта
и вещей вводятся через консоль и не зашиты в production-код.

Меню приложения:

1. добавить транспорт и пройти техосмотр;
2. добавить вещь на баланс;
3. показать количество объектов и энергопотребление;
4. показать технику для новичков;
5. показать инвентарные номера;
0. выйти.

## Тесты

```bash
cd task_1
python3 -m unittest discover -s tests -v
```

Тесты проверяют поведение модели и сервисов: правило новичков, валидацию,
техосмотр, подмену зависимости, подсчёт энергии, инвентарные номера и
интерактивный консольный сценарий. Ввод и вывод интерфейса подменяются в тестах,
поэтому тестовые данные не нужны в production-коде.

## Модель

Любой инвентаризируемый объект предоставляет `name` и
`inventory_number` через протокол `InventoryItem`. Потребитель энергии
предоставляет `daily_energy_kwh` через протокол `EnergyConsumer`.

Транспорт хранит:

- инвентарный номер;
- суточный расход энергии;
- простоту для новичка от 1 до 10;
- признак готовности к эксплуатации для решения техосмотра.

Значение простоты `>= 6` означает, что транспорт подходит новичкам.

## SOLID

- **S.** Доменные классы хранят правила своих данных, `Fleet` отвечает за учёт и отчёты, `ServiceCenter` за решение техосмотра, `ConsoleApp` за ввод/вывод, `main.py` только за сборку приложения.
- **O.** Новый вид транспорта добавляется наследованием от `Transport` с собственным `name`; код `Fleet` менять не требуется.
- **L.** `Scooter`, `Bicycle`, `ElectricBicycle` и новый наследник `Transport` одинаково принимаются сервисом парка.
- **I.** Протоколы `InventoryItem`, `EnergyConsumer` и `InspectionService` описывают только нужные возможности.
- **D.** `Fleet` получает объект с методом `inspect` через конструктор и не зависит от конкретного `ServiceCenter`.

### Какой принцип применён наиболее явно?

Наиболее явно применён DIP: `Fleet` зависит от протокола
`InspectionService`, а не от класса `ServiceCenter`. Это видно в
`vyshkat/services.py` в конструкторе `Fleet` и позволяет менять проверку без
изменения учёта парка.

### Какой принцип сознательно ограничен?

`ConsoleApp` совмещает обработку команд, разбор пользовательского ввода и
форматирование консольного вывода. Это небольшое ограничение SRP: для большого
продукта ввод и вывод стоило бы вынести в отдельные компоненты, но здесь это
остаётся одной компактной UI-границей. Бизнес-правила при этом находятся в
`Fleet` и доменных классах.

### Что произойдёт при расширении?

- **Новый вид транспорта.** Достаточно создать наследника `Transport` и задать его название. `Fleet` уже умеет считать его, проверять техосмотр и включать в отчёты.
- **Сотрудник.** Сотрудник по условию не является объектом баланса. Его можно добавить отдельной сущностью и сервисом сотрудников, не меняя текущие правила.
- **Склад запчастей.** Можно добавить сущности запчастей с инвентарным номером и отдельный сервис склада. Если складские объекты должны входить в общий баланс, они могут реализовать `InventoryItem`; если потребляют энергию, также `EnergyConsumer`.

### Как тестируется техосмотр и как подменяется зависимость?

В `tests/test_services.py` используется `FakeInspectionService`. Он передаётся
в `Fleet` через конструктор, записывает проверенные объекты и возвращает заранее
заданный результат. Поэтому тест отдельно проверяет принятие и отклонение,
не запуская реальный `ServiceCenter`.

Для правила новичков, `test_only_score_at_least_six_is_beginner_friendly` проверяет границу `5/6`, а
`test_beginner_transports_include_only_accepted_suitable_transport` проверяет
фильтрацию уже добавленного парка.

### Что сделал ИИ?

ИИ использовался как помощник для проектирования структуры, написания
первоначального кода и тестов. В итоговой версии вручную проверены соответствие
требованиям задания, команды запуска, полный набор тестов и интерактивная работа
консольного приложения.
