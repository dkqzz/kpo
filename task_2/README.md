# ДЗ №2. ПОС

Консольное приложение на Python ("Преподавательская оценка студентов") для учёта
студентов, критериев оценивания, выставленных баллов и текущего взвешенного
итога по рубрикатору.

## Запуск

Требуется Python 3.11 или новее. Дополнительные библиотеки не нужны.

```bash
cd task_2
python3 -m pos.main
```

Приложение позволяет добавить и просмотреть студентов и критерии, выставить,
исправить или отменить оценку, посмотреть оценки студента и экспортировать итоги
в CSV. Данные хранятся в памяти только до завершения программы.

Для сквозной демонстрации задания выполните:

```bash
cd task_2
python3 -m pos.main --demo --export-path results.csv
```

Демонстрация создаёт примеры студентов и критериев, выставляет оценки,
показывает итог и сохраняет CSV. Для Excel в русской локали файл записывается в
UTF-8 с BOM, с разделителем `;` и десятичной запятой.

## Тесты

```bash
cd task_2
python3 -m unittest discover -s tests -v
```

Тесты покрывают инварианты модели, границы оценок, расчёт полного и частичного
итога, отсутствие оценок, DI репозиториев и стратегии, экспорт CSV и консольный
сквозной сценарий.

## Предметная область и инварианты

- **Студент** — оцениваемый участник курса.
- **Критерий** — пункт рубрикатора с положительными `max_score` и `weight`.
- **Оценка** — балл студента по одному существующему критерию; одна пара
  (студент, критерий) может иметь не более одной оценки.
- **Итог** — вычисляемый результат по текущим оценкам; вручную он не вводится.

`Student` и `AssessmentCriterion` — сущности. `BoundedScore` и `StudentResult` —
объекты-значения. Фасад сначала находит студента и критерий, затем
`RubricEvaluationFactory` создаёт оценку и применяет верхнюю границу критерия.
Балл должен лежать в диапазоне от нуля до `max_score` включительно. Максимум и
вес критерия должны быть конечными положительными числами.

Веса считаются относительными и не обязаны в сумме давать 1 или 100. Текущий
итог из 10 считается только по критериям, по которым уже выставлены оценки:

$$
\text{Итог} =
10 \cdot
\frac{\displaystyle\sum_{i \in G} w_i \cdot \frac{s_i}{m_i}}
     {\displaystyle\sum_{i \in G} w_i}
$$

Здесь $G$ — множество оценённых критериев, $w_i$ — вес критерия, $s_i$ —
выставленный балл, а $m_i$ — максимальный балл по критерию.

Так пропущенная оценка не превращается в ноль. Если оценок пока нет, итог не
рассчитан и в CSV остаётся пустая ячейка. Результат округляется до двух знаков
по правилу `ROUND_HALF_UP`.

## Архитектура

Используется **Ports and Adapters (Hexagonal Architecture)**. Направление
зависимостей:

```text
presentation -> application -> domain
infrastructure -> domain ports
main.py -> собирает зависимости
```

- `pos/domain/` — сущности, объекты-значения, инварианты, доменный сервис,
  стратегия расчёта и порты репозиториев.
- `pos/application/` — `PosFacade`, который связывает сценарии работы с портами.
- `pos/infrastructure/` — in-memory репозитории и CSV-экспорт.
- `pos/presentation/` — интерактивная консоль и повторяемая демонстрация.
- `pos/container.py` — компактный DI-контейнер: создаёт адаптеры, стратегию и
  фасад.
- `pos/main.py` — composition root, который запускает интерактивный режим или
  demo.

Домен не импортирует консоль или CSV. В текущем задании не нужны база данных,
импорт ведомостей, несколько курсов, пересдачи и апелляции, поэтому достаточно
in-memory репозиториев и одного адаптера экспорта.

## GoF и DI

- **Порождающий — Factory Method.** `RubricEvaluationFactory` связывает оценку с
  уже существующими студентом и критерием и создаёт `BoundedScore` по максимуму
  критерия.
- **Структурный — Facade.** `PosFacade` даёт консоли единый вход к сценариям
  добавления, выставления оценки, расчёта и экспорта.
- **Поведенческий — Strategy.** `WeightedAverageStrategy` инкапсулирует правило
  расчёта; `StudentResultCalculator` получает его через конструктор.
- `PosFacade` также получает репозитории, фабрику и экспортёр через конструктор.
  В тестах инфраструктуру и стратегию можно заменить небольшими fake-объектами.

## Что сделал ИИ?

ИИ использовался как помощник для проектирования структуры, написания
первоначального кода и тестов. В итоговой версии вручную проверены соответствие
требованиям задания, команды запуска, полный набор тестов и интерактивная работа
консольного приложения.
